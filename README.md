# Pixel Studio

iPhoneの縦向きとWindowsのブラウザで使う、Godot 4向け2D素材制作のためのドット絵エディタです。Phase 1と端末内自動保存・PWAを実装しています。上部のロゴや紹介文を置かず、起動後すぐ編集できます。

## 実装範囲

- 新規キャンバス：16×16、32×32、48×48、幅・高さそれぞれ1〜256 pxの自由設定（長方形も可）
- 1ピクセルのペン、透明に消す消しゴム、4方向接続の塗りつぶし、スポイト
- 8色のプリセットと自由な色指定。透明画素のスポイトは消しゴムに切り替え
- 整数座標の補間による連続描画。指・マウス・ペンのPointer Events
- グリッド切り替え、全体表示を基準に1／2／4／8／16倍のズーム、表示位置の移動
- 1ストローク／1回の塗りつぶし単位で50操作のUndo / Redo
- 元の幅・高さと透明度を保持したPNG出力、ダウンロード・iPhoneの共有／画像保存導線
- IndexedDBに編集中の1作品を自動保存し、再起動時に復元
- PWAのインストール案内、初回キャッシュ後のオフライン起動・編集・PNG出力
- GitHub Actionsによるテスト・ビルド・GitHub Pagesへの自動デプロイ

レイヤー、アニメーション、タイルセット管理、UI枠・戦闘画面編集、JSONプロジェクト保存、Godot専用出力、クラウド同期は未実装です。

## 開発

Node.js 24とnpmを使用します（`.nvmrc`）。

```sh
cd /workspace/dotmake # ローカルPCの場合はチェックアウト先
npm ci
npm run dev
```

開発サーバーはポート5173を使用します。PWAのService Workerは開発モードでは登録しません。本番ビルドとプレビューサーバーで検証してください。

```sh
npm run build
npm run preview
```

ローカルPCの画面をiPhoneで確認するときは同じLANのPCのアドレスを使用できます。ただし、PWA／Service Workerの実機確認にはHTTPSの公開サイトが必要です（PCのlocalhostは開発用の例外です）。

## 操作

- **新規作成**：プリセットまたは自由サイズを選びます。「作成して置き換える」で現在の作品・履歴を置き換えます。取り消す場合はキャンセルします。作品を残すには先にPNGを書き出してください。
- **描画**：ツールと色を選び、キャンバスをドラッグします。塗りつぶしとスポイトはタップします。描画中は指でページがスクロールしません。ページのスクロールは表示領域の外で行ってください。
- **ズーム**：「＋」「−」で全体表示に対して拡大・縮小します。「全体表示」でリセットします。1倍でも大きなキャンバスは表示領域からはみ出る場合があり、移動ツールで端まで移動できます。
- **移動**：「移動」を選び、キャンバス表示領域をドラッグします。画素と履歴は変わりません。ピンチズームは未実装です。
- **グリッド**：表示だけの線です。1画素の表示幅が4 CSS px未満のときは描画を見やすくするため線を省略します。拡大すると表示されます。
- **透明**：市松模様は背景の目印です。消しゴムで画素を透明にできます。PNGに市松模様やグリッドは入りません。
- **PNG出力**：プレビュー画面で「PNGを保存」を選びます。iPhoneはプレビュー画像の長押しや、対応環境では「共有」から保存することもできます。
- **キーボード**：`B` ペン、`E` 消しゴム、`F` 塗りつぶし、`I` スポイト、`H` 移動、`G` グリッド。`Ctrl / ⌘ + Z`でUndo、`Ctrl / ⌘ + Shift + Z`または`Ctrl + Y`でRedo。ダイアログや入力欄で編集中はショートカットを抑制します。

## 自動保存と復元

起動時にIndexedDBから画像サイズ・RGBA画素を復元します。読み込みが完了するまで編集は開始しません。ストロークが終了したとき、塗りつぶし・Undo / Redo・新規作成の後に保存し、トランザクション完了後に「この端末に保存済み」と表示します。履歴、選択色・ツール・表示位置は再起動で初期状態に戻ります。

保存が失敗した場合はエラーを表示し、PNG出力は引き続き利用できます。初回の読み込みに失敗した場合は、読み取れなかった既存データを空白で上書きしません。編集内容をPNGで退避するか、新規作成で明示的に保存を再開してください。

自動保存はバックアップやクラウド同期ではありません。同じ作品を複数タブで同時編集すると、後から保存した方が残ります。1タブで使用してください。ブラウザのサイトデータ削除、ストレージの整理、プライベート閲覧、保存完了前の強制終了では作品が失われる可能性があります。大切な作品はPNGでも保存してください。ブラウザ版とホーム画面版のストレージ共有はOS・ブラウザに依存します。

## PWA

1. 初回はオンラインで公開サイトを開きます。
2. 「オフラインで使用できます」の表示を確認します。
3. iPhoneのSafariでは共有メニュー →「ホーム画面に追加」。WindowsではEdge／Chromeのインストール操作を使用します。
4. 以後はキャッシュが残っていれば、オフラインでも起動・編集・端末内保存・PNG出力ができます。

更新は編集中に強制適用しません。「新しいバージョンがあります」が表示されたら、保存完了後に「保存して更新」を選びます。Service Workerが利用できない場合もオンライン編集は可能で、準備失敗の表示が出ます。PWAの更新・インストール・iOSの画像保存は実機確認が別途必要です。

## 設計

```text
src/
  model/       RGBA画像、編集状態・履歴、色・ツールの型
  drawing/     線の補間、4方向塗りつぶし、スポイト、座標変換、Canvas転送
  io/          PNGエンコード、IndexedDB、復元・自動保存フック
  components/  Canvas入力と表示、サイズ指定・PNG出力ダイアログ、PWA状態
  App.tsx      UIの組み立てと各操作の接続
  styles.css   縦向き優先のレスポンシブUI
public/        PWAアイコン
tests/        ブラウザ上の操作・画素・保存・オフライン検証
```

画像の正本はCanvasではなく`PixelDocument`のRGBA配列です。Canvasは表示、PNG出力は独立したCanvasへの転送で行います。ズーム・移動・グリッドは画素データに影響しません。履歴はイミュータブルなスナップショットを保持します。Pointer Cancel・キャプチャ喪失・画面回転・非表示で描きかけのストロークを1操作として確定します。将来のレイヤーやアニメーション用の複雑な基盤は作っていません。

## 自動検証

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium # 初回のみ
npm run test:e2e
```

既存Chromiumを使用する環境：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

ブラウザテストは本番ビルドを作り、専用のプレビューサーバーを起動・終了します。デスクトップとiPhone相当の画面・タッチ設定のChromiumで検証します。iPhoneプロファイルはiOS Safariそのものではありません。デスクトップ側のタッチ専用テスト1件は対象外としてスキップします。

画素のRGBA値、線の連続性、4方向の塗りつぶし、透明消去、履歴、キャンバス外でのリリース、操作中断、回転、2本目の指の無視、サイズ指定、ズーム・タッチ移動、実際に保存したPNGのサイズ・画素・透明度、IndexedDB復元、読み込み／書き込み失敗、マニフェスト・アイコン、オフライン再起動と描画を検証します。

### iPhone実機で確認すること

- Safari縦向きで、ノッチ・ホームインジケータに操作部が重ならないこと。
- 左上・右下の隅をタップし、狙った1マスに描けること。速い横線・縦線・斜線が途切れないこと。
- 描画中にページがスクロールせず、表示領域の外でページをスクロールできること。
- 指を領域外で離した後や、描画中の回転・アプリ切り替え後に、描画状態が残らないこと。
- 2本目の指が触れても余計な点・線が入らないこと。
- 拡大後に「移動」で指ドラッグでき、ペンに戻すと正しいマスに描けること。
- 塗りつぶしの境界、色と透明のスポイト、消しゴム・Undo / Redoが正しいこと。
- 16／32／48と縦長・横長の自由サイズで四隅まで編集できること。
- PNGプレビューを長押し、ダウンロード、対応時の共有から保存できること。画像の寸法・透明背景を確認すること。
- 保存済みを確認してSafariを閉じ、再度開くと画像・サイズが復元されること。
- 「ホーム画面に追加」後に単独ウィンドウで起動し、一度オンラインで準備してから機内モードでも再起動・描画・復元・PNG保存できること。
- 次回公開時に更新通知が出て、保存してから更新できること。

WindowsではChrome／Edgeで同様の描画、ウィンドウサイズ変更、キーボード、インストール・オフライン起動・PNGダウンロードを確認してください。

## GitHub Pages

リポジトリの **Settings → Pages → Source: GitHub Actions** を使用します。`main`へpushすると単体テスト・Pagesと同じサブパスでのブラウザテスト後にデプロイします。PRでは検証のみを行います。

Viteのbase・PWAのscopeとstart_urlはリポジトリ名に合わせます。`dotmake`では`/dotmake/`です。ローカルで同条件を確認する場合、ビルド・プレビュー両方で同じ環境変数を指定します。

```sh
VITE_BASE_PATH=/dotmake/ npm run build
VITE_BASE_PATH=/dotmake/ npm run preview
# または、自動テストも同じパスで実行
VITE_BASE_PATH=/dotmake/ npm run test:e2e
```

独自ドメインや`owner.github.io`直下で公開する場合はbaseを`/`にしてください。
