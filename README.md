# Pixel Studio

iPhoneの縦向きとWindowsのブラウザを想定した、ドット絵エディタの最小版です。最初の到達点は「32×32の絵を描いて、消して、元に戻せる」ことです。

## 実装済み

- 起動時に32×32の透明なキャンバスを作成
- 1ピクセルのペン・消しゴムと8色のパレット
- Pointer Eventsによる指・マウス・ペン入力
- 高速なドラッグも整数座標で補間し、線を連続描画
- 1ストローク単位のUndo / Redo（直近50操作、変更のない操作は除外）
- グリッドの表示切り替え。市松模様・グリッドは表示だけで、画素には含まれません
- 縦向き優先のUI、横向きへの回転時も画素・履歴を保持
- GitHub Actionsのテスト・Pagesデプロイ設定

**この版は作品を保存しません。リロード・ページを閉じる操作で画素と履歴が消えます。** 画面にも注意を表示しています。PCの離脱確認は補助機能で、iOSのアプリ終了を防ぐものではありません。

## 起動

Node.js 24とnpmを使用します（`.nvmrc`）。

```sh
cd /workspace/dotmake # ローカルPCの場合はチェックアウト先
npm ci
npm run dev
```

開発サーバーは既定でポート5173を使用します。ローカルPCで実機確認する場合は、同じLANのiPhoneからPCのLANアドレスとポート5173で開いてください。クラウド環境では提供されている接続方法を利用してください。

## 操作

- キャンバス内でドラッグすると描画します。描画中はキャンバスのページスクロールを抑制します。ページのスクロールはキャンバス外で行ってください。
- 「消しゴム」は画素を透明にします。色の選択でペンに戻ります。
- 右上の矢印でUndo / Redoできます。描画中は履歴の操作を無効にします。
- 複数の指が触れても描画するのは最初の1本だけです。ピンチズームは未実装です。
- 狭い画面ではパレットを横にスワイプして残りの色を選べます。短い画面ではツールを見るためにページをスクロールする場合があります。
- PC：`B` ペン、`E` 消しゴム、`G` グリッド、`Ctrl / ⌘ + Z` Undo、`Ctrl / ⌘ + Shift + Z` Redo。`Ctrl + Y`でもRedoできます。

## 設計

```text
src/
  model/       RGBA画素データ、編集状態・履歴の純粋な更新
  drawing/     整数座標の線描画、画面座標変換、Canvasへの転送
  components/  CanvasのPointer EventsとUI部品
  App.tsx      ツール・色の選択、エディタの組み立て
  styles.css   縦向き優先のレスポンシブUI
tests/         ブラウザの操作・実画素検証
```

画像の正本はCanvasではなく`PixelDocument`のRGBA配列です。履歴はイミュータブルな画像のスナップショットを保持します。Pointer Cancel、キャプチャ喪失、画面の回転・非表示は描きかけのストロークを1操作として確定します。将来の保存・PNG出力はこの画素データから行う想定で、この版では空の入出力基盤やレイヤー構造は作っていません。

## 検証

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium # 初回のみ
npm run test:e2e
```

既存Chromiumを使用する環境では、例として次のように指定できます。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

ブラウザテストは本番ビルドとプレビューサーバーを使います。デスクトップとiPhone相当の画面サイズ・タッチ設定を持つ**Chromium**で、画素のRGBA値、線の補間、透明消去、履歴、キャンバス外でのリリース、操作中断、回転、実タッチイベントと2本目の指の無視を検証します。iPhone設定のテストはiOS Safariそのものの検証ではありません。デスクトップ側のタッチ専用テスト1件は意図してスキップします。

### iPhone実機で確認する操作

- Safariを縦向きで開き、画面上部・下部がノッチやホームインジケータと重ならないこと。
- 左上・右下の隅にタップし、狙ったマスだけに描けること。
- 指でゆっくり／素早く、横線・縦線・斜線を描き、線が途切れないこと。
- 描画中にページがスクロールせず、キャンバス外ではページをスクロールできること。
- キャンバス外へ指を動かして離し、次のタップまで線が描かれ続けないこと。
- 2本目の指を置いても余計な点や線が入らないこと。
- 消しゴムで市松模様に戻り、Undoで元の色に戻ること。
- 長い1ストロークがUndo1回で消え、Redo1回で戻ること。
- 横向き→縦向きに回転しても描画内容と履歴が失われないこと。
- 描画途中の回転・別アプリへの切り替え後、描画を再開できること。
- パレットの横スワイプ、ボタンの押しやすさを小さい画面でも確認すること。

WindowsではChromeまたはEdgeで同様の描画・画面サイズ変更・キーボード操作を確認してください。実機確認は自動テストとは別に必要です。

## GitHub Pages

1. GitHubのリポジトリ設定で **Pages → Build and deployment → Source: GitHub Actions** を選びます。
2. コードを`main`にpushします。Actionsが依存導入・単体テスト・ブラウザテスト・ビルド後にPagesへデプロイします。
3. 公開先はActionsの`github-pages`環境に表示されます。PRでは検証のみを行います。

Pagesビルドはリポジトリ名からViteの`base`を設定します。`dotmake`なら`/dotmake/`です。手元で同条件のビルドを行う場合：

```sh
VITE_BASE_PATH=/dotmake/ npm run build
VITE_BASE_PATH=/dotmake/ npm run preview
```

この設定ファイルの用意だけでは公開されません。GitHubへのpush、Pages設定、Actionsの成功が必要です。独自ドメインや`owner.github.io`直下で公開する場合はbaseを`/`に変更してください。
